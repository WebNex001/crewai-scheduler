## 1. 技术选型总览

### 1.1 技术栈矩阵

| 层级 | 技术选型 | 版本 | 选型理由 |
|------|----------|------|----------|
| **前端框架** | 原生HTML5 + CSS3 + JavaScript (ES6+) | - | 轻量级、无构建依赖、学习成本低、满足MVC分离需求 |
| **前端UI库** | Bootstrap 5 | 5.3.x | 响应式布局、组件丰富、易于定制 |
| **后端框架** | Flask | 3.0.x | 轻量灵活、扩展性强、适合中小型项目 |
| **Web服务器** | Flask内置开发服务器 → Gunicorn | 21.2.x | 生产环境WSGI容器，支持多进程 |
| **数据库** | SQLite → PostgreSQL | 3.x / 15.x | 开发便捷（SQLite），生产可升级（PostgreSQL） |
| **ORM** | SQLAlchemy | 2.0.x | 成熟的Python ORM，支持多种数据库 |
| **认证** | Flask-Login + JWT | 0.6.x / 2.x | 会话认证+JWT令牌双支持 |
| **表单验证** | WTForms | 3.1.x | CSRF防护、表单验证一体化 |
| **任务调度** | APScheduler | 3.10.x | 内置定时任务，支持到期提醒 |
| **日志** | Python logging + ELK（预留） | - | 结构化日志，生产可接入ELK |

### 1.2 技术选型决策说明

```
技术选型原则：轻量优先、最小复杂度、最大扩展性

1. 为什么选择 Flask 而非 Django？
   ✓ 项目定位为轻量级任务管理，无需Django的全栈功能
   ✓ Flask的扩展机制允许按需引入，保持代码库精简
   ✓ 学习曲线更平缓，适合快速迭代

2. 为什么选择 SQLite 作为默认数据库？
   ✓ 零配置、零运维，开箱即用
   ✓ 单文件存储，便于开发和演示
   ✓ PostgreSQL兼容，架构预留升级路径
   ✓ 5000-10000条任务记录内性能无明显瓶颈

3. 为什么前端不使用React/Vue？
   ✓ 需求未涉及复杂状态管理和实时交互
   ✓ 原生JS + Bootstrap 足以满足CRUD操作
   ✓ 降低技术栈复杂度，减少构建工具依赖

4. 为什么引入APScheduler而非系统cron？
   ✓ 跨平台、支持Python进程内调度
   ✓ 可精确控制任务执行时间和并发数
   ✓ 便于后续扩展为分布式任务队列
```

### 4.2 分层约束

```
架构原则说明：
1. 每一层只能调用其下层的服务，不能跨层调用
2. API层负责请求/响应，不包含业务逻辑
3. Service层是所有业务逻辑的唯一入口
4. Domain层（Models）仅定义数据结构和关系，不包含业务逻辑
5. 基础设施层（数据库、外部服务）通过Repository模式封装

调用方向：API → Service → Models → Infrastructure
```

## 8. 技术决策总结

### 8.1 关键决策点

| 决策项 | 选型 | 替代方案 | 选型理由 |
|--------|------|----------|----------|
| Web框架 | Flask | Django, FastAPI | 轻量灵活，扩展性强，符合项目定位 |
| 数据库 | SQLite/PostgreSQL | MySQL, MongoDB | 关系型数据，SQLAlchemy ORM支持 |
| 认证方式 | JWT + Session | 纯Token | 兼顾Web页面和API需求 |
| 前端技术 | 原生JS + Bootstrap | React, Vue | 降低复杂度，满足CRUD需求 |
| 任务调度 | APScheduler | Celery Beat | 单进程内调度足矣，预留升级空间 |
| 表单验证 | WTForms | Pydantic | 与Flask深度集成 |

### 8.2 风险与缓解

| 风险 | 等级 | 缓解措施 |
|------|------|----------|
| SQLite并发写入瓶颈 | 中 | 预估并发<50用户，生产环境迁移PostgreSQL |
| JWT令牌泄露 | 高 | 短期令牌 + 刷新机制 + 黑名单 |
| XSS攻击 | 中 | CSP策略 + Jinja2转义 |
| 数据丢失 | 高 | 每日备份 + 数据库迁移脚本版本化 |
| 团队协作权限漏洞 | 中 | 细粒度RBAC + 操作审计日志 |
